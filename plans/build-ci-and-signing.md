# Сборка, CI и подпись

## Сборки на GitHub Actions, не на EAS

Владелец в России и **не может оплатить EAS**; бесплатная очередь EAS может простаивать 50+
минут. Поэтому нативные APK собираются на бесплатных hosted-раннерах GitHub.
`.github/workflows/build-android.yml`:

1. checkout → setup-node 20 → setup-java 17
2. `npm ci`
3. **`npm test`** — гейт jest; упавшие тесты блокируют APK.
4. **номер сборки:** `versionCode` = минуты с 01.01.2026 по UTC, кладётся в
   `LIVEBEAT_VERSION_CODE` (см. «Номер сборки» ниже).
5. `npx expo prebuild --platform android --clean`
6. **подставить стабильный keystore** (см. ниже) — под guard'ом, так что no-op, если его нет.
7. `./gradlew assembleDebug -PreactNativeArchitectures=arm64-v8a`
8. `./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a`
9. **подписать standalone релизным ключом** (`scripts/sign-release-apk.sh`), если заданы секреты
   репозитория; без секретов шаг ничего не меняет (см. «Релизный ключ» ниже).
10. загрузить артефакты: **`livebeat-devclient-apk`** и **`livebeat-standalone-apk`**.

- `eas.json` лежит в корне как **запасной вариант**. Если EAS реально понадобится, запускай
  `npx eas-cli` напрямую — **не** добавляй `eas-cli` в `package.json` (его зависимость
  `dtrace-provider` ломала установку раньше).
- Воркфлоу запускается только по `push` и вручную, **не по `pull_request`**: секреты
  репозитория недоступны чужим веткам и форкам. Так и оставлять.

## Два APK

- **dev-client** (`assembleDebug` → `livebeat-devclient-apk`): нужен доступный Metro-бандлер
  (`expo start`) — для итераций с рабочей машины. Всегда подписан debug-ключом.
- **standalone** (`assembleRelease` → `livebeat-standalone-apk`): JS вшит внутрь; работает
  без ПК. **Именно его владелец ставит, чтобы тестировать вдали от стола**, и именно его
  загружают в магазин. Подписан релизным ключом, если заданы секреты, иначе debug-ключом.
- **только arm64-v8a** — сборка всех ABI давала APK ~95 МБ; только-arm64 — то, что нужно его
  телефону, и держит размер маленьким.

## Как запустить сборку

Пуш в `master` (или `main`), либо запуск воркфлоу вручную (`workflow_dispatch`).
В этом окружении **нет `gh` CLI**; чтобы проверить запуск, открой страницу Actions в браузере:
`github.com/RZhurakovskiy/Live-Beat/actions`.

## Номер сборки (`versionCode`)

Раньше он нигде не был задан, и у каждой сборки получалась единица. Для обновлений через
магазин этого мало: и RuStore, и сам Android принимают обновлением только сборку с большим
номером, а понижение версии Android запрещает.

- Номер считает шаг воркфлоу: минуты, прошедшие с 01.01.2026 00:00 UTC (на 02.10.2026 это
  около 395 000). Растёт сам, **не зависит от номера запуска** (в новом репозитории он
  начнётся с единицы, а номер сборки обратно уменьшаться не должен) и с огромным запасом
  влезает в int.
- Его читает `app.config.js` (динамическая часть конфига рядом со статичным `app.json`) и
  кладёт в `android.versionCode`. Остальные поля `android` переносятся как есть. Разбор и
  защита от мусора в `plugins/buildNumber.js`, тесты в `src/__tests__/buildNumber.test.ts`
  (среди них проверка, что `package` остался `com.pulsetracker.app`).
- Без CI (локальный запуск) номер 1, как раньше.
- **Имя версии** (`version` в `app.json`, сейчас 1.0.0) по-прежнему поднимается руками при
  выпуске: это то, что видит человек.
- ⚠️ Установленную сборку нельзя «обновить» более старым артефактом: номер у него меньше,
  Android откажется. Старый APK придётся сначала удалить (с экспортом истории).

## Стабильная подпись APK (чтобы обновления не требовали удаления)

**Проблема:** `expo prebuild --clean` пересоздаёт **случайный** `debug.keystore` каждый прогон.
Так как release подписывается debug-конфигом, у каждой сборки была **другая подпись** → Android
отказывался обновлять поверх и требовал полного удаления (с потерей данных) на каждой новой сборке.

**Решение:** фиксированный keystore закоммичен в **`signing/debug.keystore`** и копируется
поверх сгенерированного `android/app/debug.keystore` после prebuild (шаг 6). Это PKCS12-keystore
(сделан OpenSSL) со стандартными Android debug-реквизитами:
alias `androiddebugkey`, пароль стораджа и ключа `android`, что совпадает с debug signingConfig
Expo, поэтому патчить gradle не нужно. И dev-client, и standalone подписываются **одним** ключом
→ новые сборки ставятся поверх существующего приложения и сохраняют данные.

- Сгенерированная папка `android/` в gitignore; коммитится только `signing/debug.keystore`
  (`.gitignore` блокирует `*.jks`/`*.p12`/`*.pem`/`*.key`, но не `*.keystore`).
- Коммитить debug-keystore безопасно/стандартно для личного sideload-приложения (его пароль
  публичный). Реальный релизный ключ отдельный секрет, в репозиторий не попадает никогда.

> ⚠️ **Claude не может закоммитить keystore.** Bash-классификатор авто-аппрува блокирует коммит
> любого `*.keystore` как утечку учётных данных, даже этого публичного debug-ключа. Если keystore
> когда-либо нужно поменять, **владелец** запускает `git add … && git commit && git push` для него сам.

## Релизный ключ (обязателен до первой загрузки в RuStore)

С debug-ключом в магазин **нельзя**, ни одной, даже пробной загрузки:

- `signing/debug.keystore` лежит в **публичном** репозитории, пароль `android` общеизвестен.
  Любой может подписать им свою сборку, и Android примет её как «обновление» LIVEBEAT.
- Магазины обычно отклоняют APK с отладочным сертификатом.
- Магазин запоминает подпись **первой** загрузки, дальше все обновления только тем же
  ключом. Потеря ключа = больше никаких обновлений этого приложения в магазине.

**Состояние на 02.10.2026.** Владелец назвал RuStore главным вопросом дистрибуции, решение
«отложить до роста функционала» (30.09.2026) снято. Всё, что можно сделать в коде, сделано:

| Шаг | Кто | Статус |
|---|---|---|
| Экспорт и импорт всей истории (веха 1), чтобы смена ключа не стирала данные | код | сделано |
| `versionCode` растёт сам | код | сделано (выше) |
| CI подписывает standalone релизным ключом из секретов | код | сделано, проверено на настоящем APK, ждёт секретов |
| Создать релизный ключ, хранить вне репозитория в двух местах | **владелец** | не сделано |
| Добавить четыре секрета в репозиторий GitHub | **владелец** | не сделано |
| Один раз удалить приложение на телефоне и импортировать историю | **владелец** | после первой сборки с ключом |

**Как работает подпись в CI** (`scripts/sign-release-apk.sh`). После `assembleRelease` берёт
`app-release.apk` и переподписывает его официальным `apksigner` ключом из секретов; ключ
декодируется во временную папку и удаляется. Секреты репозитория (Settings → Secrets and
variables → Actions):

| Секрет | Что это |
|---|---|
| `RELEASE_KEYSTORE_BASE64` | файл ключа `.p12`, закодированный в base64 |
| `RELEASE_KEYSTORE_PASSWORD` | пароль файла ключа |
| `RELEASE_KEY_ALIAS` | имя ключа внутри файла (в инструкции `livebeat`) |
| `RELEASE_KEY_PASSWORD` | пароль самого ключа; **необязателен**, у PKCS12 он равен паролю файла |

- **Секретов нет:** шаг пишет «Релизный ключ не задан» и завершается успешно, APK остаётся с
  debug-подписью, как до этого изменения. Пока ключа нет, сборки ведут себя по-старому.
- **Ключ задан, а чего-то не хватает, пароль неверный, alias не найден, base64 битый:** шаг
  падает, до загрузки артефакта дело не доходит. Выпустить APK с чужой подписью по ошибке
  нельзя.
- **В секрет по ошибке положили сам `debug.keystore`:** отпечаток подписи после «подписания»
  не меняется, шаг падает с понятным сообщением.
- В логе шага остаётся отпечаток сертификата SHA-256: его стоит записать рядом с ключом и
  сверять при следующих сборках.
- Проверено локально на настоящем `app-release.apk` из CI (два десятка случаев: верный ключ,
  пустые секреты, неверный пароль, неверный alias, мусор вместо base64, debug-ключ в секрете,
  переводы строк в base64, подбор `apksigner` среди нескольких build-tools). Подписанный APK
  проходит `apksigner verify` (схемы v2 и v3), выравнивание `zipalign` (4 байта и 16 КБ для
  `.so`) сохраняется. **В самом CI подпись ещё не гонялась: секретов нет.** Первый прогон с
  ключом смотреть по логу шага.
- Dev-client остаётся на debug-ключе, он в магазин не идёт.

**Создание ключа, секреты, первая загрузка и остальной чек-лист для магазина** (политика
конфиденциальности, тексты карточки, обоснования разрешений, открытые вопросы) собраны в
**`rustore.md`**. Ключ владелец создаёт сам: пароль не должен попасть ни в чат, ни в репозиторий.

⚠️ После первой сборки с релизным ключом она **не ставится поверх** нынешней (подпись другая).
Порядок: экспорт истории в «Настройках» → удалить приложение → поставить новое → импорт.
Дальше все обновления, и из CI, и из RuStore, ставятся поверх. `keytool` на машине владельца есть,
но только внутри Android Studio (`C:\Program Files\Android\Android Studio\jbr\bin`), в PATH его нет.

## Локальные проверки перед любым коммитом

```
npx tsc --noEmit --noUnusedLocals   # типы
npx jest                            # 32 набора, 369 тестов (на 04.10.2026)
```

`tsconfig.json` требует `isolatedModules`, `rootDir: "."` и
`exclude: ["node_modules","src/__tests__"]` для связки TS 6 + ts-jest. Jest закреплён на 29
(совместимость с SDK 57).
