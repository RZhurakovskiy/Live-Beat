# План реализации редизайна — по этапам

Составлено 29.09.2026 после того, как владелец закрыл все восемь открытых вопросов.
Источники: `redesign-brief.md` (что за макеты), `redesign-gaps.md` (что конкретно отличается
и какие решения приняты). **Этот файл — про порядок работ.**

Принцип: каждый этап заканчивается зелёными гейтами, а крупные — сборкой APK, чтобы владелец
пощупал на телефоне. Он итерирует по ощущениям на железе, поэтому показывать, а не копить.

Гейты перед любым коммитом:

```
npx tsc --noEmit
npx jest
```

Коммиты — **без атрибуции Claude/Anthropic** (правило №1 в `conventions-and-status.md`).

## ✅ Как завершать тренировку — решено

В макетах кнопки «Завершить» нет ни на одном из пяти экранов активной тренировки, и это
пришлось закрывать отдельно. **Решение владельца:** долгое нажатие ставит на паузу и
показывает **оверлей с двумя кнопками — «Продолжить» и «Завершить»**. Пауза становится
осознанной точкой решения, случайно завершить нельзя.

Остаётся мелочь: для `welcome` нужна **фотография** (бегунья на рассвете). Пока её нет, на
её месте карточка с брендовым градиентом — подставить `<Image>` можно не трогая вёрстку.

## Этап 3 — поиск датчика, три состояния

Один экран `ScanDevice`, три вида.

- [x] **Сканирование:** бейдж `ПОИСК`, крупный заголовок, анимированный радар
      (`components/ScanPulse.tsx`) вместо системного спиннера, контурная «Отмена».
- [x] **Найдено:** бейдж `НАЙДЕНО`, строки с ID датчика и полосками сигнала
      (`components/SignalBars.tsx`), подсветка выбранного зелёной рамкой.
- [x] **Смена флоу:** тап *выбирает*, подключает нижняя кнопка «Подключить».
- [x] **Ошибка:** бейдж `ОШИБКА`, красный круг, текст, «Повторить» + «Выбрать другой датчик».

**Решения по ходу:**
- `rssi` приходит с каждым рекламным пакетом, поэтому запись устройства теперь **заменяется**,
  а не игнорируется при повторной находке — иначе полоски были бы мёртвые. Чтобы они не
  дёргались на каждый пакет, `barsForRssi` режет dBm на четыре корзины.
- Первый найденный датчик выбирается автоматически, а «Magene» перебивает выбор, если
  появится позже — кнопка «Подключить» рабочая сразу, но рекомендованный побеждает.
- Скан останавливается **перед** подключением: на Android активный скан замедляет и
  расшатывает коннект.
- `BottomCta` получил `variant` — «Отмена» в макете контурная, а не градиентная.

## Этап 5 — пауза тренировки (только логика)

Отдельным этапом и **до** вёрстки активного экрана: это изменение стора и черновика, мешать
его с версткой не надо. Всё тестируемое — покрыть тестами.

- [x] `sessionStore`: `pausedAt` + `pausedMs` в `ActiveWorkout`, экшены `pauseWorkout` /
      `resumeWorkout`.
- [x] Длительность считается **за вычетом пауз** — новый чистый модуль
      `workout/workoutTime.ts` (`workoutElapsedMs` / `workoutElapsedSec` / `resumedFrom`),
      чтобы экран, итоги и черновик пользовались одним определением «сколько шла тренировка».
- [x] На паузе в тренировку не попадает **ничего**: ни семплы пульса, ни точки трека.
      Калории и время в зонах считаются из семплов, так что исключаются сами собой.
      `liveBpm` при этом продолжает обновляться — датчик работает, просто не записывается.
- [x] `currentBpm` на паузе обнуляется: число на экране не должно выглядеть живым, когда
      ничего не пишется.
- [x] Точки геолокации на паузе отбрасываются в сторе, а задача трекинга не
      останавливается — дёргать её на каждую паузу рискованнее, чем отфильтровать точки.
- [x] `workoutDraft` сохраняет паузу; `workoutDraftCodec` читает старые черновики без этих
      полей как «никогда не паузился» и отбрасывает бессмысленные метки (из будущего,
      раньше старта, отрицательные).
- [x] Тесты: 13 новых (`workoutTime.test.ts` + дополнения к кодеку). Итого **5 наборов / 59**.

**Решения по ходу:**
- **Метрики строки зависят от режима.** У дорожки нет ни дистанции, ни темпа, поэтому она
  показывает калории и средний пульс вместо трёх прочерков.
- **Неделя считается с понедельника** (`startOfWeekMs`), а не с воскресенья.
- Дистанцию недели можно суммировать без фильтра по режиму: `distanceMeters` есть только у
  уличных сессий, так что сумма уже и есть «дистанция (улица)».
- Новые чистые хелперы в `format.ts` (`startOfWeekMs`, `formatRelativeDate`,
  `formatTotalTime`, `formatTimeOfDay`) покрыты тестами — включая переход через границу
  месяца, где «вчера» легко посчитать неверно.

## Этап 9 — статистика

Владелец оставил экран и попросил расширить: «через него много чего можно узнать о своём
прогрессе». Вся новая математика — **чистые модули с тестами**.

- [x] Итоги за 7/30 дней и время в зонах переведены на общий язык (`SectionCard`,
      `FilterChips`, `ScreenTitle`).
- [x] **Пульс на сравнимом темпе** (`utils/progress.ts` → `paceEfficiency`). Логика:
      уличные пробежки ≥ 1 км группируются в полосы по 15 с/км, берётся **самая населённая**
      полоса, и старшая половина сравнивается с младшей. Меньше четырёх пробежек в полосе —
      возвращается `null`, и экран честно пишет «нечего сравнивать» вместо выдуманной цифры.
      При нечётном числе средняя пробежка выбрасывается, а не считается дважды.
      Подпись всегда называет полосу темпа и число пробежек и предупреждает про шум.
- [x] **Динамика по неделям** (`weeklyBuckets` + `components/WeeklyBars.tsx`) — 8 недель,
      **включая пустые**: пропуск должен быть виден. У пустой недели остаётся серая полоска,
      иначе столбец выглядит потерянным, а не нулевым. Метрика — километры, а если уличных
      тренировок нет вовсе, то время.
- [x] **Личные рекорды** (`personalRecords`) — дистанция, длительность, темп.
      ⚠️ Рекорд темпа считается только на дистанции **≥ 1 км**: иначе двухсотметровый рывок
      навсегда занял бы строку. Длительность учитывает и дорожку, дистанция — только улицу.
- [x] Тестов +14, итого **9 наборов / 103**.

⛔ Не выдумывать: VO2max, тренировочная нагрузка, восстановление, набор высоты, каденс, шаги,
«+N% за неделю». Этих данных в модели нет.
